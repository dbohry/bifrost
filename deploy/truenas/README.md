# TrueNAS SCALE app

`bifrost/` is a draft of Bifrost's entry for the TrueNAS apps catalog
([truenas/apps](https://github.com/truenas/apps)), community train. It is based
on the `beszel-hub` app there, which has the same shape: one Go binary with its
own health check and one data volume.

It is kept here so it can be reviewed with the rest of Bifrost. The catalog
itself lives in `truenas/apps`, at `ix-dev/community/bifrost/`.

## What it sets up

- One container, `dbohry/bifrost`, running as the TrueNAS `apps` user (568:568) by
  default. The user and group can be changed in the install form.
- `BIFROST_ADDR` is set from the port chosen in the form (default 30560) and
  `BIFROST_DATA_DIR` is `/data`.
- `/data` is an ixVolume by default, or a host path. A permissions container makes
  it writable by the chosen user before Bifrost starts.
- The health check runs `/bifrost healthcheck`, because the image has no shell or
  curl.
- A "Web UI" button in TrueNAS, and a note that the first visitor creates the
  administrator account.

## Before submitting

1. **Use the newest release.** `bifrost/ix_values.yaml` pins `1.0.2` by digest, as
   every app in the catalog does, and `bifrost/app.yaml` has the same `app_version`.
   If a newer version is out when you submit, update both. The digest is the
   `Digest:` line at the top of:

   ```bash
   docker buildx imagetools inspect dbohry/bifrost:1.0.2
   ```

   Once the app is in the catalog, TrueNAS's own tooling bumps it on new releases.
2. **Ask first.** Open an issue in `truenas/apps` proposing the app (text below) and
   wait for a maintainer to agree.
3. **Copy and test.** Fork `truenas/apps`, copy `bifrost/` to
   `ix-dev/community/bifrost/`, then from the root of the fork:

   ```bash
   devbox run copy-lib
   ```

   ```bash
   ./.github/scripts/port_validation.py
   ```

   ```bash
   ./.github/scripts/generate_metadata.py --app bifrost --train community
   ```

   ```bash
   ./.github/scripts/ci.py --app bifrost --train community --test-file basic-values.yaml --wait=true
   ```

   `copy-lib` fills in `lib_version_hash`. If `port_validation.py` reports that
   30560 is taken, use one of the free ports it lists in `questions.yaml`. If a newer
   library than 2.3.18 is in `library/`, set `lib_version` to it first.
4. **Open the PR** with their "App Addition" template (text below), attaching
   `docs/logo.svg` as the icon and the two screenshots from `docs/screenshots/`.

## Issue text

> **New app: Bifrost**
>
> Bifrost (https://github.com/dbohry/bifrost) is a small, self-hosted start page
> for apps and services: one Go binary and one SQLite file, multi-user, about 580
> app logos built in, themes, and optional status checks. MIT licensed. The image
> `dbohry/bifrost` is published for amd64 and arm64 with semver tags.
>
> It runs as any non-root user, needs one data volume and nothing else. I'm the
> upstream author and would like to add it to the community train and keep it
> working. Would a PR be welcome?
